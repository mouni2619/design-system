# Mandark Design System

Design tokens, foundations and components for Mandark products.

Two libraries are in play and they do not overlap. **Bootstrap** supplies the
reset, the grid and the utility classes — no Bootstrap components are loaded.
**Ant Design** supplies the components. Both are fed the same tokens from
`src/tokens/`.

## Architecture at a glance

```
src/tokens/*.js          <- single source of truth (plain JS, unitless)
   |
   +-- mirrored in --> src/styles/_variables.scss
   |                        |  $theme-colors, $spacers, $border-radius-*,
   |                        |  $box-shadow-*, $body-color
   |                        v
   |                   src/styles/bootstrap.scss   (ordered import list)
   |                        v
   |                   :root { --bs-* }  and  .bg-* .text-* .m-* .p-* .rounded-*
   |                        v
   |                   className="..." in stories and docs blocks
   |
   +-- imported ----> src/theme/antdTheme.js -> ThemeProvider -> ConfigProvider
   |                        v
   |                   AntD cssinjs injects <style> at runtime -> AntD components
   |
   +-- imported ----> src/docs/data/*.js -> src/docs/blocks/*.jsx -> foundations/*.mdx
```

Three consumers, one source. The first arm is CSS authored at build time by
Sass. The second is CSS generated by Ant Design at runtime — there is no antd
stylesheet to import. The third is the documentation reading token values as
plain data, which is why a swatch can print its own hex. Both style arms are
entered globally from `.storybook/preview.jsx`.

The SCSS layer mirrors the token values by hand, so a color, spacing or radius
change is two edits: `src/tokens/` and `src/styles/_variables.scss`.

Three conventions are easy to get wrong:

- **Values are unitless.** The consumer adds the unit — `_variables.scss` writes
  `4px`, `antdTheme.js` passes the bare `4`.
- **`ShadowGeometry` carries no color.** Whoever consumes it appends a grey.
- **`emp-N` is emphasis step N** — position N on the parent 10-step palette, so
  `primary-emp-1` is `blue-100`. The unsuffixed base is always step 600.

## The Bootstrap arm

Every Bootstrap variable is declared `!default`, so it only takes effect if
nobody assigned it first. Our values must land **before**
`bootstrap/scss/variables` is imported or they are silently discarded — that
ordering is the whole reason `src/styles/bootstrap.scss` exists, and its
numbered comments spell out each stage.

Every radius step is pinned explicitly. Bootstrap's defaults are in `rem`, so an
unset step both drifts with the root font size and renders something other than
what the docs label it. Border widths are the exception — Bootstrap's defaults
are already `1px`..`5px`, matching `BorderWidthTokens`, so nothing is restated.

### What we generate by hand

Bootstrap has no API for these, so `_variables.scss` loops them out: `.w-1`..
`.w-8` from `$spacers`; the `h1..h6` rules from `$headings`, which sets size,
line height and letter spacing together; `.shadow-primary` and friends from
`$focus-shadows`; `.text-disable`, `.bg-body`, `.bg-disable`, `.default` and
`.border-disable` from the custom color maps. `_typography.scss` adds `body` and
`caption`, the two scale steps with no heading tag of their own.

These loops emit *before* `bootstrap/scss/utilities/api`, so a class name
Bootstrap also generates wins over ours. Pick names Bootstrap does not use —
that is why `.text-body` is left to `$body-color` rather than declared in
`$custom-text-colors`.

## The Ant Design arm

`src/theme/antdTheme.js` is a plain `theme.token` object built from the same
token imports. `src/theme/ThemeProvider.jsx` mounts it in a single
`ConfigProvider` — the sole Storybook decorator, and what a consuming app should
mount once at its root.

Three conversions are not obvious:

- **`lineHeight` is a unitless ratio**, `LineHeight.body / FontSize.body` = 1.5.
  AntD multiplies it by the font size; Bootstrap takes px.
- **Heading sizes are pinned** through `fontSizeHeading1..5`. Left alone, AntD
  derives its own scale from `fontSize` and drifts off our eight steps.
- **Shadows are assembled here** — `ShadowGeometry` gives the geometry, this file
  appends `gray-400`.

The radius slots sit on the same rungs as the utilities: `borderRadius: 6` is
`--bs-border-radius` is `RadiusTokens.md`. When you add a value to one arm, add
the matching rung to the other, or the two render differently for the same
intent.

No `algorithm` and no per-component `components` overrides are configured yet.
See the `// TODO: Update the AntD Config` marker in that file.

## Why both Bootstrap and Ant Design

**Bootstrap is loaded for its CSS surface, not its components.**
`bootstrap.scss` imports reboot, the grid, type and the utilities API — nothing
from `bootstrap/scss/buttons`, `forms`, `modal` or `dropdown`. What we take is a
reset, a responsive grid and a token-driven layer of utility classes that any
markup can use, including markup that is not a component and never will be:
docs pages, story layouts, one-off screens.

**Ant Design is loaded for its components.** Accessible, behaviour-heavy widgets
— date pickers, selects, tables, modals — are the expensive things to build.
AntD supplies them and accepts our tokens through `ConfigProvider`, so we
configure it rather than restyle it from the CSS side.

The two solve different problems: AntD has no `d-flex` or `m-3`, Bootstrap has
no `<DatePicker>`, and running both means neither gets stretched into the
other's job. The Button stories are exactly this — AntD components positioned
with Bootstrap utilities. `Button.jsx` wraps AntD behind `@components/Button` so
the import path never reveals the implementation; the reason to depend on AntD
is time to market, not lock-in, and the wrapper is what keeps it swappable.

## Import convention

Import the specific topic, not a folder. `@tokens` and `@docs` deliberately
have no barrel file, so a bare `from "@tokens"` will not resolve.

```js
import { FontSize } from "@tokens/typography"; // yes
import { FontSize } from "@tokens";            // no
```

This keeps dependencies greppable — `@tokens/shadow` finds every shadow
consumer — which matters as the SCSS variables move to being generated from
`src/tokens/`.

**Every internal import is aliased.** Relative paths are not used anywhere in
`src/`, including for a file's own siblings and its stylesheet:

```js
import { CopyBadge } from "@docs/blocks/primitives"; // yes
import { CopyBadge } from "./primitives";            // no
import "@docs/blocks/blocks.css";                    // yes, even for CSS
```

The aliases are defined in `.storybook/aliases.js` and mirrored in
`jsconfig.json` so the editor resolves them too — add a new one to both.

## Adding a component

Copy `src/components/Button/`. Each component is a folder with `Name.jsx`,
`Name.stories.jsx` and an `index.js`. Components that wrap Ant Design sit
alongside ones written from scratch — the import path should not reveal which
is which, so the implementation stays swappable.
